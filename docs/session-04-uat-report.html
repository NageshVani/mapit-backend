Changes Applied This Session (Search Redesign)

BUG-S4-01 — CORS rejection returned HTTP 500 instead of 403

Severity: Medium · File: src/server.js · Commit: dc8199a

When a disallowed origin hit any API endpoint, the CORS callback called cb(corsErr) but corsErr.statusCode was not set — Express defaulted to 500. A 500 triggers monitoring alerts and reveals an unexpected server error to clients when the correct semantic is "forbidden by access policy".

- const corsErr = new Error('Not allowed by CORS'); cb(corsErr); + const corsErr = new Error('Not allowed by CORS'); corsErr.statusCode = 403; cb(corsErr);

BUG-S4-02 — Stack trace included in 4xx error responses in dev mode

Severity: Medium · File: src/middleware/errorHandler.js · Commit: dc8199a

The errorHandler was including stack: err.stack in development for all errors, including 4xx responses (validation failures, auth rejections, CORS errors). These are user-visible responses; including file paths and stack frames leaks implementation detail.

- ...(process.env.NODE_ENV === 'development' && { stack: err.stack }), + ...(process.env.NODE_ENV === 'development' && statusCode >= 500 && { stack: err.stack }),

CHANGE-S4-03 — Nominatim location search replaced with header keyword search + map viewport filter

Type: Feature redesign · File: MapIt_MVP_v1.html · Commit: 093d49f

Arun UAT observation: the Nominatim forward-geocoding search in the header bar was replaced with a keyword search that filters currently-loaded listings by title/details text AND constrains results to the current map viewport. This is faster (no API call), works offline, and respects the user's current map zoom and pan context. ~90 lines of Nominatim code removed. ST.searchCenter, _searchMarker, fetchLocSuggestions, renderLocDD, pickLocResult, kwrdBox/kwrdIn sidebar elements all removed.

- srchIn: "Search a location…" → Nominatim API call → blue pin → reload from new coords + srchIn: "Search listings by keyword…" → filter ST.listings by q AND map.getBounds() → instant result

CHANGE-S4-04 — Explore Area search mode added: pan map to search any area

Type: New feature · File: MapIt_MVP_v1.html · Commit: efabd47

New "Search Mode" toggle in the Browse sidebar. "📍 My Locations" (default) searches from the user's saved pin as before. "🗺 Explore Area" makes the map centre the search origin — a blue dot tracks the centre in real-time; the radius circle turns blue; panning the map reloads listings 800ms after the pan stops (moveend debounce). Toggle is greyed out on Saved/My Ads tabs. Arun tested and commended: "That was really good."

+ setSearchMode(mode): ST.exploreMode toggle; blue dot (_placeExploreMarker); move+moveend listeners + activeLoc(): returns map.getCenter() when ST.exploreMode is true + _onExploreMoveEnd(): clearTimeout + setTimeout(loadListings, 800) + circleColor: '#3B82F6' (blue) in explore mode, '#F06030' (orange) in My Locations

CHANGE-S4-05 — Satellite tile toggle simplified: CartoDB Voyager is now hardcoded default

Type: Simplification · File: MapIt_MVP_v1.html · Commit: 093d49f

The 🛰 satellite toggle button and associated _voyagerLayer / _satLayer / _satOn variables were removed as part of the search simplification commit. CartoDB Voyager remains as the sole tile provider (inlined in map init). The Explore Area mode provides an equivalent discovery mechanism — panning to any area on the Voyager map already shows the required context without needing a satellite overlay.

Observations

OBS-01 — public/og-image.png not yet created

OG meta tags are correctly wired (og:image and twitter:image both reference https://www.mapit.co.in/og-image.png). The image file itself does not yet exist. WhatsApp and Twitter link previews will fall back to no thumbnail image until a 1200×630px PNG is placed at public/og-image.png. This is a manual design task — not a code change. Assign to Nagesh or a designer before Session 9 public launch.

OBS-02 — Keyword search relies on already-loaded listings — no server call

The new keyword search filters ST.listings in-memory. This means: (a) it only searches within the current radius fetch (listings already loaded near the user's active location); (b) panning the map updates the viewport filter but does NOT trigger a new API fetch — that only happens via the Explore Area mode. For the MVP family-beta scale this is correct behaviour. Document for Arun: keyword search narrows what's already loaded; Explore Area pans to reload from a new centre.

OBS-03 — uat.mapit.co.in still points to production (Vercel free tier)

Custom branch-specific domains require Vercel Pro. UAT testing must use the Vercel preview URL: https://mapit-backend-git-uat-nagesh-n-arun.vercel.app. Upgrade Vercel to Pro in Session 7 to fix this (budget approved: $20/mo).

OBS-04 — CONTEXT.md "Important Context" CORS list is stale

The "Important Context" section of CONTEXT.md still lists localhost:3000, localhost:3001, localhost:5500, 127.0.0.1:5500 in the CORS origins. These were removed in commit dc8199a. The "Decisions Made" section is correct. Update CONTEXT.md to reflect the current allow-list.

OBS-05 — Explore Area mode + keyword search combination: intended interaction

When both Explore mode is active AND a keyword is typed: activeLoc() returns the map centre (so loadListings() fetches from map centre), but filtered() additionally constrains by keyword AND getBounds(). The two features compose cleanly — pan to an area, type a keyword, get only keyword-matching listings visible in that map view.
