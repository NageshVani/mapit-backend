Listing Approval Process

For Arun · prepared by James for Nagesh · 31 Oct 2026 · Session 9L (review queue)
Status: server side built and tested on UAT (42 automatic checks pass). The review page itself, the seller screens and the release to mapit.co.in are still to come (section 9).
In one paragraph: every listing is checked by a person before buyers can see it. Checking moves out of the admin page into its own phone page, www.mapit.co.in/review, so more people than Nagesh and you can do it, starting with both your wives, and hired staff later. Each reviewer gets one listing at a time and chooses Approve, Needs change or Reject. Nothing is ever deleted by a reviewer: a listing that is not approved stays with the seller, with the reason, so they can fix it and send it again.

3. When a seller posts a listing

  1. The listing is saved as Pending. Buyers cannot see it. The seller sees "Pending review" in My Listings.
  2. An automatic AI check reads the title and description. If it is unsure (for example, a phone number in the text), the listing gets a 🚩 flag and the AI's reason. The flag is a hint for the reviewer, never an automatic rejection.
  3. The admin mailbox listings@mapit.co.in gets an alert, as today.
  4. The listing joins the review queue. The queue is first come, first served: the seller who has waited longest is reviewed first.

Skip
  • No double work: when an approver opens a listing it is held for them for 5 minutes. Two approvers tapping Next at the same moment always get two different listings.
  • Phone dies or approver walks away: after 5 minutes the hold runs out and the listing goes back into the queue by itself.
  • Skip: hands the listing back so someone else can take it (useful when unsure).
  • Nobody reviews their own listing. This includes admins.
  • After each decision the next listing loads, until the queue shows "All clear 🎉".

Reasons only appear under the right button, so an approver can't send a fixable listing a "Not approved" message by mistake. New reasons can be added any time from real experience; it is a small code change, no database work.

Notes are shown to the seller. Approvers should write them politely and never include anything private.

6. When a seller edits a listing

  • Any edit sends the listing back to the queue, whatever its state: live, pending, "Needs change" or "Not approved". It is checked again before buyers see the new version.
  • ⚠️ A live listing that is edited disappears from the map until it is approved again. This is why quick reviews matter, and worth telling sellers.
  • The listing keeps its original place in the line, so a fixed listing is usually reviewed quickly.
  • Edited while an approver is looking at it: the approver's tap is refused with "This listing just changed. Loading again." Nobody can approve text they did not see.
  • The seller can still delete a listing or mark it sold at any time.

7. Joining and leaving the review team

  1. A new approver signs up on /review with email, a strong password and an email code (same as the main app).
  2. The page then says "Waiting for approval". Signing up alone gives no access.
  3. Nagesh or Arun opens Team on /review and taps Activate. From then on the person can review.
  4. Revoke works at once, on the approver's very next tap. A revoked person cannot request access again; only an admin can reactivate them.
Strangers can create an account on /review, but it does nothing until an admin activates it. Unknown requests can simply be revoked.

8. Safety and records

  • Privacy: approvers never see a seller's phone, email or exact location, only the first name and area name. This matters most once outside staff join.
  • Every decision is recorded: who decided, when, the reason and the note. Useful for checking a new approver's quality.
  • Nothing is deleted by reviewing. Today's admin "Remove" (a permanent delete, seller never told why) is replaced by Needs change / Reject.
  • Taking down a listing that is already live (for example after a buyer's report) stays with admins on /admin. "Remove with a reason" for that case is planned separately (9H).
