Session 4 — Address Entry + Quick Wins

Original scope: Nominatim forward geocoding in post-listing form  ·  Next session up

Up Next
Original Planned Scope
🗺️ Forward geocoding (address → lat/lng) — Nominatim search field in post-listing form; user types an address, picks from dropdown, pin placed automatically. This is Tester-6 item 2, explicitly tagged for Session 4. ~2 hrs
🔴 Critical Additions (non-negotiable before public launch)
✉️ Email verification — step-verify-email — Change POST /api/auth/signup backend from email_confirm: true (admin API, skips verification) to email_confirm: false and add a new step-verify-email modal step after account creation that accepts a 6-digit OTP from Resend. Currently anyone can register with another person's email — this is the single highest-risk pre-launch gap documented in CONTEXT.md. ~3 hrs
🔍 PostGIS GiST index verification — While building the Nominatim geocoding route, run EXPLAIN ANALYZE on the listings haversine query and confirm "Index Scan" (not "Seq Scan") on the lat/lng columns. If missing, add the GiST index: CREATE INDEX ON listings USING gist(ll_to_earth(lat, lng)). 10-minute check that prevents performance degradation post-launch. ~15 min
🟣 Added Improvements (high value, low effort)
🌐 CORS localhost removal — Remove localhost:3000, localhost:3001, localhost:5500, 127.0.0.1:5500 from the CORS allowlist in src/server.js. These are dev-only origins that must not be reachable from the production Express server. Nagesh can keep them in a local .env.development override. 5-minute change. ~5 min
🔗 Open Graph / social sharing meta tags — Add <meta property="og:title">, og:description, og:image, and og:url to the <head> of MapIt_MVP_v1.html. When a listing link is shared on WhatsApp (the primary sharing channel in India), a rich preview card appears instead of a bare URL. Static values for now (app-level, not per-listing). ~20 min
⚡ Leaflet preload + Google Fonts non-blocking — Add rel="preload" for the Leaflet JS CDN link and change the Google Fonts <link> to use media="print" onload="this.media='all'". These two one-line changes eliminate the two biggest render-blocking resources on the first paint — directly addresses the slow-mobile performance issue on Indian 4G connections. ~10 min
🗺️ Evaluate Geoapify vs Nominatim for production geocoding — The OSM Nominatim usage policy prohibits heavy commercial use from the shared server. Session 4 is building the geocoding feature — decide at the start of that session whether to use Nominatim (free, no key, rate-limited) or Geoapify free tier (2,500 req/day, API key, reliable). If going public soon, build it against Geoapify from day one to avoid a later re-integration. Decision only

Session 5 — Notifications & Platform Hardening

New session · No original scope · Full session of pre-launch-critical improvements

New Session
🔴 Critical — Highest conversion and trust impact
📩 Seller notification email when buyer presses "I'm Interested" — Currently the most significant conversion gap: a buyer taps "I'm Interested", the message is stored in the DB, and the seller has no notification whatsoever — no email, no SMS, no push. They only see an inbox badge the next time they open the app. Add a Resend email trigger in POST /api/messages: "Someone is interested in your listing [title]. Open MapIt to see their message." This one change meaningfully increases seller response rates and marketplace trust. ~1.5 hrs
⏰ Listing expiry notification email (3 days before) — Listings expire at 30 days (Session 3). Sellers currently get no warning — listings just disappear. A Vercel Cron job (available on Pro plan, set to daily) queries SELECT * FROM listings WHERE expires_at BETWEEN NOW() AND NOW() + INTERVAL '3 days' AND status='active' and sends a Resend email per seller: "Your MapIt listing '[title]' expires in 3 days. Renew it to stay listed." Dramatically reduces ghost listings and keeps sellers engaged. ~2 hrs
🔴 Critical — Security
🔐 Row Level Security (RLS) full audit — all tables — Systematically verify RLS policies on every table: listings, profiles, messages, user_pins, invite_codes. For each table: confirm RLS is enabled, read the policy definition, and test that an unauthenticated Supabase client cannot read data that should be private. A misconfigured policy could expose all user profiles or all messages to a direct Supabase query. spatial_ref_sys is intentionally unrestricted (PostGIS system table) — leave it alone. ~2 hrs
🟣 Additions — Quality and operations
🗑️ Orphaned photo cleanup job — When a listing is deleted, its photos remain in Supabase Storage with no corresponding DB row. A scheduled job (or a DELETE trigger) should clean these up. Approach: add an ON DELETE CASCADE trigger or a Vercel Cron that runs SELECT storage_path FROM listing_photos WHERE listing_id NOT IN (SELECT id FROM listings) and calls the Supabase Storage delete API. Prevents Storage filling up silently after months of use. ~1 hr
💬 Structured feedback form upgrade — Add a category dropdown (Bug / Content Report / Suggestion / Other) and a 1–5 star rating field to the feedback form. Store both in the feedback table (add columns via migration). This makes post-launch feedback triage 5× faster — currently all reports arrive as unstructured free text with no priority signal. ~1 hr
✉️ Supabase Auth email template branding — Update OTP email templates in Supabase Dashboard → Auth → Email Templates. Replace the default "Supabase Auth" subject and generic body with MapIt branding: "Your MapIt verification code is [OTP]" as the subject, with the MapIt 📍 pin, brand colour (#f06030), and a short "You're signing into MapIt — India's first exact-location marketplace" tagline. Not code — a Supabase Dashboard task, but easily forgotten and very visible to every new user. ~20 min (Supabase Dashboard)

Session 7 — Vercel Pro + Security Hardening

Original scope: Vercel Pro upgrade ($20/mo)  ·  Budget: upgrade before this session (architecture.md)

Planned
Original Planned Scope
▲ Vercel Free → Pro upgrade — Enables Vercel Cron Jobs (needed for the expiry notification job from Session 5), branch-specific custom domains (uat.mapit.co.in will finally point to the UAT branch, not production), higher function limits, and team collaboration for Arun's access. The budget is approved at $20/mo. ~30 min
🔴 Critical Additions
⚖️ Legal pages — Privacy Policy and Terms of Service — Two static routes: GET /privacy and GET /terms, served as HTML pages from public/privacy.html and public/terms.html. Content: a plain-language Privacy Policy covering data collected (email, location, listing content), how it is stored (Supabase India region), and contact details; and a Terms of Service covering acceptable use, listing rules, and dispute resolution. Both are required: (1) Indian IT Act SPDI Rules mandate a published privacy policy; (2) Google's OAuth consent screen requires a linked privacy policy URL or Google disables the Sign in with Google button for new users. Link both from the ToS checkbox in step-profile. ~2 hrs (drafting + coding)
🔍 Sentry error monitoring — npm install @sentry/node, add Sentry.init({ dsn: process.env.SENTRY_DSN }) to server.js, wrap Express error handler. Sentry free tier = 5,000 errors/month with email alerts. This closes the biggest operational blind spot: currently, silent 500 errors on Vercel serverless functions go completely undetected until a user reports them. The SENTRY_DSN env var gets added to Vercel project environment variables. ~30 min
🟣 Additions — Security
🛡️ Helmet CSP re-enablement — Currently disabled globally (contentSecurityPolicy: false) because of inline <script> blocks and CDN resources. Once email verification (Session 4) removes the last inline auth scripts, write an explicit CSP policy that: allows cdn.jsdelivr.net (Leaflet), cdnjs.cloudflare.com (Font Awesome), fonts.googleapis.com, and uses a nonce or sha256- hash for any remaining inline scripts. A proper CSP is the strongest single defence against XSS on the frontend. ~1.5 hrs
🔔 Vercel deployment and error alerts setup — Configure Vercel to send email alerts on: (1) failed deployments, (2) function error rate spikes. Also configure Sentry to alert on: first occurrence of any new error type, and error rate above threshold. Takes 15 minutes in two dashboards but means you are never the last to know about a production problem. ~15 min

Session 8 — Admin Dashboard + Performance

Original scope: unplanned (placeholder session)  ·  Now anchored to admin tooling and performance audit

Planned
🟣 New Content (this session was unplanned)
🖥️ Proper admin dashboard page — Replace the current hardcoded admin email check with a dedicated /admin route (Express middleware guards it to admin emails only). Page shows: total listings by status (pending / active / expired / sold), new users today/week, messages sent today, listing reports queue, recent feedback entries. Moves all admin tasks off the Supabase Dashboard into the app itself — critical once listing volume makes manual DB browsing impractical. ~3 hrs
📊 Performance audit — Lighthouse on mobile emulation — Run a Lighthouse audit on mapit.co.in in Chrome DevTools → Lighthouse → Mobile → Performance. Target: First Contentful Paint <2s on simulated 4G. Identify the top 2–3 opportunities (typically: Leaflet render-blocking, unused CSS in the single file, uncompressed photos). Fix what is low-effort (preload hints, image quality cap at upload time). Document what remains for v2. ~1 hr
🤖 robots.txt + sitemap.xml — Add public/robots.txt (Allow: /, Disallow: /api/, Sitemap: https://mapit.co.in/sitemap.xml) and a static public/sitemap.xml with the root URL. Add a static route in Express to serve /sitemap.xml. Ensures Google indexes the app correctly and does not crawl API endpoints. 20-minute task that can be overlooked entirely without a dedicated session for it. ~20 min
🔌 Supabase PgBouncer connection pooler setup — At 50+ concurrent users, Vercel serverless functions will exhaust Supabase's 20 direct connection limit (Free tier). PgBouncer is available on Supabase Pro as a one-line connection string change: swap the direct connection string for the pooler string in the backend .env and Vercel environment variables. Session 8 is the right time — after Pro upgrade (Session 7) but before the connection limit is hit at launch. ~20 min

Session 9 — Supabase Pro + Public Launch Gate

Original scope: Supabase Pro upgrade ($25/mo)  ·  Budget: upgrade before this session (architecture.md)

Launch Gate
Original Planned Scope
🗄️ Supabase Free → Pro upgrade — Unlocks: daily automated backups with 7-day retention, Point-in-Time Recovery (PITR), higher connection limits, Storage CDN, compute upgrades, and no row-count limits. Budget approved at $25/mo. Before upgrading, run the SQL cleanup tasks (delete empty-details listings, fix TVS SCOOTY subcategory) documented in CONTEXT.md. ~30 min
🔴 Critical Additions — Launch gate checks
📸 Enable Supabase Storage CDN — At Pro upgrade, explicitly toggle the CDN on in Supabase Dashboard → Storage → CDN. Without it, every listing photo request hits the Supabase origin server. With it, photos are cached at edge nodes globally — dramatically faster for Indian users and reduces egress costs. Also enable Supabase Image Transformations to serve photos at reduced resolution for thumbnails vs full-view, cutting bandwidth by ~60%. ~10 min (Dashboard toggle)
✅ Pre-launch security and readiness checklist run — A final automated check session: (1) verify CORS allows only production + UAT origins — no localhost; (2) verify Helmet CSP is active and shows in response headers; (3) verify RLS is enabled on all tables; (4) verify Sentry is receiving test errors; (5) verify legal pages are live at /privacy and /terms; (6) verify email verification flow end-to-end; (7) verify expiry notification cron fires correctly; (8) verify Google OAuth redirect URLs in Supabase; (9) confirm SUPABASE_SERVICE_ROLE_KEY does not appear in any client-visible response. If all 9 pass — the app is launch-ready. ~1.5 hrs
🟣 Additions
💾 Verify backup and PITR configuration — In Supabase Dashboard → Settings → Backups: confirm daily backups are scheduled, confirm PITR window (7 days on Pro). Do a test restore of a table to a temporary DB to confirm the backup is actually restorable — not just that the backup job ran. This is the one disaster-recovery verification that is always skipped until the day it is needed. ~30 min
🚦 Controlled launch — soft open before public announcement — Before any social media push or press: share the live URL with 10–20 people outside the family test group (trusted extended network). Run for 48 hours, monitor Sentry for any new error types, check Vercel logs for unexpected patterns. Only proceed with the public announcement after this soft-open is clean. This approach catches integration issues that family testers with known devices and known data never trigger. Process, not code

External / Non-Code Tasks

These cannot be done by writing code or running git — they require dashboard actions, external registrations, or legal work. Assign to Nagesh or Arun explicitly.

📜

Twilio DLT Registration (TRAI)

SMS OTP via Twilio requires TRAI DLT (Distributed Ledger Technology) registration for India delivery. Register your entity at traidlt.com with company name, PAN, and contact details. Link the approved DLT header to Twilio. Without this, Indian SMS OTPs will be blocked by carriers post-2021 TRAI mandates.

👤 Nagesh — external portal · ~2 days processing
⚖️

Privacy Policy + Terms of Service — Legal Review

The legal pages built in Session 7 cover the content. Before publishing, have a lawyer (or at minimum a compliance-aware friend) review the Privacy Policy for SPDI Rule compliance under the IT Act. Focus areas: data categories collected, storage location, user rights, and grievance officer contact (mandatory under Indian law for digital platforms).

👤 Arun — legal contact · Before Session 9 launch gate
📧

Resend Plan Upgrade → Starter ($20/mo)

Free tier is 100 emails/day. With seller notifications (Session 5), expiry reminders, OTP emails, and password reset emails at public scale, this limit is breached by ~50 daily active users. Upgrade to Starter (50,000 emails/month) before the Session 9 launch. Can be done in the Resend dashboard in 2 minutes.

👤 Nagesh — Resend dashboard · Before Session 9
🔑

Google OAuth Consent Screen — Privacy Policy URL

Google requires a published Privacy Policy URL on the OAuth consent screen before approving the app for public use. After the legal pages are live (Session 7), update the Google Cloud Console → OAuth consent screen → Privacy Policy URL field. Without this, new users see a warning: "This app hasn't been verified by Google" — which kills sign-ups.

👤 Nagesh — Google Cloud Console · After Session 7
🌐

Nominatim / Geocoding API Key (Geoapify)

If Session 4 decides to use Geoapify instead of OSM Nominatim for production geocoding: create a free Geoapify account, get the API key, add GEOAPIFY_KEY to .env.example and Vercel environment variables. Free tier: 2,500 requests/day — more than enough for MVP. Paid tier scales per usage.

👤 Nagesh — Geoapify dashboard · During Session 4
📱

UAT on Real Devices — Low-End Android

Before public launch, test the full listing post + browse + "I'm Interested" flow on a Redmi or Samsung Galaxy A-series phone (the most common budget Android in India). Use Chrome on Android, not desktop mobile emulation. Pay attention to: touch target sizes, the keyboard pushing up the map, photo upload on a real camera roll, and GPS accuracy indoors.

👤 Nagesh + any family member · Before Session 9 launch gate
