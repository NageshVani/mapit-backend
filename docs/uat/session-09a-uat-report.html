💡 Observations

OBS-01 — A manual click-through is not enough for auth-adjacent features

The first version of email verification passed a full live click-through by Nagesh — signup, OTP screen, code received, profile setup, app opened. It looked completely done. It wasn't: the backend never actually required the OTP step at all, because this Supabase project silently overrides the confirmation flag. A manual UI walkthrough only exercises the happy path a real user would take; it can't discover that a *different* request (skip the OTP screen, call sign-in directly) succeeds when it shouldn't. That's specifically what the automated curl-based testing phase of this report caught.

OBS-02 — Platform-level auto-confirm was an undocumented, non-obvious project setting

Nothing in the codebase or prior session notes flagged that this Supabase project auto-confirms new accounts regardless of the email_confirm admin-API parameter. This was only discovered by directly inspecting account state via supabaseAdmin.auth.admin.listUsers() immediately after creation — the API call itself returns success either way, giving no signal that the flag was ignored. Worth remembering for any future auth-adjacent work in this project: verify assumptions about Supabase account state empirically, don't trust API parameters to behave as named.

OBS-03 — Test-account cleanup needed twice, second attempt hit an unanticipated FK

Debugging this feature created many nagesh.aadi+xxxx@gmail.com throwaway accounts. The first cleanup script attempt failed on feedback_user_id_fkey — the same class of foreign-key gotcha documented previously for the real nagesh.aadi@gmail.com account. Revised script (database/cleanup-test-alias-accounts.sql) now clears every table that can reference profiles(id) before touching profiles/auth.users — not yet run.

OBS-04 — Not yet merged to main

The 3-bug fix is on uat (PR #7) but not yet promoted to main/production as of this report. The original (broken) email-verification code from PR #6 is what's currently live on mapit.co.in — meaning the authentication bypass described in T-012 is theoretically present in production right now, until #7 is merged. Recommend prioritizing that merge.
